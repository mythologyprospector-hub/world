# Fresh-Agent Handoff

## Point of entry

You are arriving in the **mythologyprospector-hub world**, not merely into one repository.

Read this file first, then:

1. `WORLD.md`
2. `WORKFLOW.md`
3. `REPOSITORIES.md`
4. `MACHINE.md`

Then inspect the relevant project's own README and canonical documents.

## Operating model

The human owns the world and is the final approval gate.

The assistant is the foreman/steward/architect/driver.

Codex performs implementation labor.

GitHub is the durable project record.

GitHub Actions and `work.yml` are the first verification layer where established by the project; human testing follows when appropriate.

A lone `.` means:

**accepted — proceed — continue — find the next thing.**

## Critical rule

Do not assume the current conversation contains the project's history.

Recover project state from GitHub.

Do not assume one repository contains the whole world.

Use this repository to orient yourself, then enter the relevant project's own canon.

## Work discipline

Inspect before modifying.

Do not guess.

Do not silently invent architecture.

Do not silently absorb one project into another.

Keep durable documentation synchronized with meaningful work.

Prefer the smallest correct, testable step.

## Human communication

Keep reports short.

The human wants enough information to remain in control, not a transcript of implementation details.

## Arrival command

After reading the world documents, inventory the current GitHub/project state and determine:

- what is active;
- what is complete;
- what is unresolved;
- which project actually owns the next piece of work.

Then proceed according to that project's canon.
